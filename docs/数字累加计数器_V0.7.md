# 数字累加：板端每秒加一，持续显示

日期：2026-11-15。需要 **SDK0.7.0 + 声明standalone_counter能力的固件0.7.0**。0.6固件可以继续运行原有固化流程，但不能执行新增计数器。当前内容为本地实现说明；编译、实机及现场观察结果由 [verification](verification.md) 分项记录，不因文档存在而视为通过。

本机COM5已升级并实际验证：无SDK会话时按秒累加，15次只读采样约14.235秒从52到66；用户确认“每秒正常加一，显示正常”。当前计数保持运行，未自动清除。实际拔USB改独立电源的操作未声称完成，重启起点/Flash边界按本篇说明处理。

## 1. 运行哪个文件

[examples/portable/16_counter.py](../examples/portable/16_counter.py) 可单独复制并运行，只导入ai_robot。默认ST7735S128×160、rotation=1后有效画面160×128，SCL/SCK4、SDA/MOSI5、CS15、DC7、RES/RST6、BLK16；COM5和IO按实际连接修改。

```python
from ai_robot import Program, Robot

program = Program()
program.display.set(panel="st7735s_128x160", SCL=4, SDA=5,
                    CS=15, DC=7, RES=6, BLK=16, rotation=1)
program.display.fill("black")
program.display.text("数字累加", x=8, y=8, color="cyan")
program.display.text("+1 / second", x=8, y=26)
program.display.counter(name="count", start=0, step=1, interval=1,
                        x=8, y=48, width=144, height=20,
                        color="white", background="black")
with Robot(port="COM5") as robot:
    robot.program.save(program, autostart=True)
```

步骤是：配置屏幕 → 画静态背景/标题 → 最后添加计数器 → 保存。保存不立即开始，关闭电脑程序后按RESET或重新接电，板端显示0、1、2、3……，每秒加一。不需要电脑保持运行，也不需要电脑端while不断上传数字。

运行会替换已保存的固化流程；若原来有重要内容，先按第5节备份。首次需升级支持计数器的固件；之后改起点、间隔、颜色或位置只需重新save，不用每次重刷固件。

## 2. 参数与行为

```python
program.display.counter(
    name="count", start=0, step=1, interval=1,
    x=8, y=48, width=144, height=20,
    color="white", background="black"
)
```

| 参数 | 含义和范围 |
|---|---|
| name | 计数控件名，ASCII字母开头，字母/数字/下划线，最长24字节 |
| start | 初始值，精确整数0～9223372036854775807；每次启动/重启从此值重新计数，默认0 |
| step | 每周期增加量，整数1～2147483647，默认1 |
| interval | 秒，有限0.05～60，保存时换算为整数毫秒；默认1秒 |
| x、y | 数字区域左上角，按旋转后的屏幕尺寸 |
| width、height | 默认144×20，最小133×16，且整个区域必须在屏内；保守容纳19位64bit数字 |
| color、background | 数字颜色和每次擦除数字区域的底色；命名色、RGB元组0～255或RGB565整数均可 |

数字区域每次更新先用background擦除，再显示新数值；静态标题和区域外图形不需要每秒重画。133像素最小宽度意味着128像素宽的竖屏不能直接用此控件，可选择匹配的横屏rotation或更宽面板。

计数保存在RAM，不每秒写Flash；start、间隔和控件配置随程序保存。重启不接着上次数值，而是回到start。调度使用毫秒时钟的无符号差值处理回绕；发生处理延迟时按已经过去的完整周期补足增量，不把每次渲染耗时不断叠加为计数周期。显示更新仍受驱动和执行调度影响，不是硬实时精度保证。

“一直增加”是在64位范围内持续运行；达到上限而下一步会溢出时报告错误并停止，不静默归零或变成负数。此版本只显示非负整数。

## 3. 为什么不写loop=True或在后面加wait

counter是持续运行的**终端步骤**，必须是主流程最后一步，不能在条件分支中，一个程序最多一个。它自己按interval推进，不需要Program.wait或root循环。

保存时使用默认`loop=False`。`save(..., loop=True)`会在SDK发送前和固件校验时拒绝，避免循环重新初始化屏幕和计数。普通不含counter的旧程序仍支持loop=True，行为不变。

## 4. 与begin/end录制一起使用

录制负责背景和静态图形；结束后给返回的Program添加计数器，再显式保存：

```python
# 同一robot已经配置屏幕并start。
robot.program.begin()
robot.display.clear()
robot.display.text("数字累加", x=8, y=8)
flow = robot.program.end()
flow.display.counter(name="count", x=8, y=48)
robot.program.save(flow, autostart=True)
```

counter是Program构建接口，不是实时Robot.display.counter接口，也不通过录制读取或截图产生。必须显式保存flow，因为end返回值与管理器保留的隐式save快照相互独立，给flow追加控件不会改写原隐式快照。

这只是一个定时累加显示控件，不是任意Python变量、传感器数据绑定或命名页面调度。页面1/页面2及其普通动态控件仍按各自能力处理，不能据此假定pages.show/text已经可离线录制。

## 5. 继续编程、清除或还原先前流程

电脑创建Robot会接管并停止板端计数。已有的program.info/download/start/stop/enable/disable/clear接口继续使用；显式start在当前会话试跑，with退出或租约到期停止。save启用的开机策略则在下次重启生效。

原来有保存内容时，测试前取得完整模型和策略：

```python
# 同一robot已连接；只有program.info()["saved"]为True时才能download。
previous = robot.program.download()
```

把previous保存到自己的本地备份位置。需要还原时：

```python
from ai_robot import Program

# previous来自测试前的完整备份，包括program、loop、enabled。
robot.program.save(Program.from_dict(previous["program"]),
                   loop=previous["loop"], autostart=previous["enabled"])
```

本轮本机测试入口在 [tests/counter](../tests/counter/README.md)：[clear_counter.py](../tests/counter/clear_counter.py)删除计数流程；[restore_previous.py](../tests/counter/restore_previous.py)使用本次私有备份`backups/counter_v070_20261115/before.json`还原测试前的固化内容和loop/enabled，不回退固件或改写全局配置。后者只在本机备份存在时可用，不是公共下载文件。

如果只要清除计数流程，也可继续运行 [screen_clear.py](../tests/standalone/screen_clear.py) 或调用`robot.program.clear()`。它清除保存流程和开机策略，保留在线屏幕/舵机配置及原默认页面；关闭会话后按已启用的默认页策略恢复。本轮测试前已有启用中的13步A/B固化，因此“清除计数”和“恢复旧A/B流程”是两项不同操作；没有备份的旧流程无法从被替换的数据中凭空找回。

读取program.info返回counter.active/name/value/interval_ms，有助于软件检查。注意新建Robot本身会接管停止开机计数，所以不能一边新建控制连接一边要求无主计数继续；不接管的只读诊断和用户现场观察在实机记录中分开处理。
