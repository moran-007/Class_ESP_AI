## 2 最短操作流程

1. 接好开发板 USB 数据线，关闭 Arduino 串口监视器等占用串口的程序。
2. 首次使用双击根目录的 `安装Python环境.cmd`。它创建项目内 `.venv`，安装 pyserial 和当前 SDK；需要可用的 Python 3.11+，首次安装依赖可能访问软件包源。
3. 双击 `运行板载灯.cmd`，应发送红、绿、蓝各两秒，随后熄灯。或者双击 `开始测试.cmd`，输入 1 查询信息、2 测灯、0 退出。
4. 自己改 Python 时打开 `tests/quick/02_rgb.py`，IDE 解释器选择 `ai_maker/.venv/Scripts/python.exe`，点击运行即可。无需填写命令行参数。
5. 先完成 01、02。外设接好后再分别运行 03～07，按文件顶部 `PIN` 修改信号引脚。

本机项目环境已创建。若只使用系统 Python，其解释器也须安装 pyserial；在某个 Python 中安装依赖，不代表其他 Python 环境自动具有依赖。

自动选择串口仅接受唯一 USB 串口候选；不会依次向所有串口发送控制命令。候选不唯一时，在 `tests/quick/settings.py` 修改一行：

```python
PORT = "COM5"
```

这里的 COM5 是当前板本次识别结果，不是固件永久绑定值。

## 3 学员代码写到什么程度

新文件放在 `tests/quick/` 内，即可使用公共连接模块：

```python
from _board import connect

with connect() as robot:
    robot.led.color("yellow")
    robot.wait(3)
```

学员只需要写操作。`connect()` 负责引用项目 SDK、按公共设置建立连接和关闭连接；`Robot` 负责握手、心跳和 JSON 协议。导入公共模块不会连接设备，进入 `with` 才连接。

`robot.led.color()` 支持 red、green、blue、yellow、white、off，默认分量亮度 16，允许通过 `brightness=8` 调低，范围 0～32。混色使用 `robot.led.set(red=16, green=8, blue=0)`。`robot.wait(秒数)` 在后台心跳失败后会中止等待并报告连接异常。

退出 `with` 会关闭会话并释放运行输出。正常程序结束时如收到明确的固件清理错误，会报告失败；正文已有异常时保留原异常。USB 突然断开、进程被强制结束等情况由板端 6 秒租约兜底。关闭串口并不代表机械装置已经停止或断电，实际状态仍须观察。

## 4 已完成的板级接口

| 功能 | 当前行为 |
|---|---|
| 设备与引脚查询 | 返回固件家族、版本、能力、RGB 引脚、资源限制、占用和当前维护状态 |
| 板载 RGB | GPIO48 默认，可明确编译为 GPIO38；发送 GRB 数据帧，检查 RMT 初始化和发送结果 |
| GPIO | 输入、内部上拉、内部下拉、输出、释放；引脚由程序指定 |
| ADC | 可用 ADC 引脚的 12-bit 原始计数，读后恢复数字输入；无校准电压值 |
| PWM | 最多 4 路，固定 1kHz，占空比整数 0～100% |
| 位置舵机 | 最多 4 路、50Hz，逻辑名称、可保存的引脚和行程/脉宽配置；默认 30～150° |
| 配置 | 独立 NVS 命名空间、修订号冲突检查、保存失败不覆盖旧映射 |
| 会话 | 单控制者、SDK 每秒心跳、6 秒超时释放；不自动重放动作 |
| 维护 | 进入后停止输出并保存标记，重启仍维护，退出不会自动移动 |

启动只发送板载灯熄灭帧，不自动配置外接 GPIO、不输出舵机脉冲、不启动音频或网络。先前白灯诊断程序的灯珠锁存状态也会被主动清除。

RGB 发送失败时，状态 `led.driver_ok=false`，颜色保留最后成功指令，不能看作当前物理颜色。停止仍会释放 GPIO 和舵机；RGB 超时故障需复位恢复。软件没有光学或舵机位置反馈，回执不等于实物动作验收。

## 5 换线与引脚

当前保守 N16R8 板型保留 GPIO0、3、19、20、26～37、43、44、45、46 和所选 RGB 引脚。它们涉及启动、存储、USB、UART 或板载资源；普通 GPIO 接口不会占用这些引脚。可用例子包括 GPIO1、2、4～18、21、38～42、47（本板 RGB48 版本）；最终以 `01_device_info.py` 返回的 reserved、owner 和能力为准，也要核对排针是否实际引出。

输入与输出能力、ADC 能力、系统保留、资源占用是不同概念。当前 S3 SDK 的输出能力掩码与有效 GPIO 掩码一致；本工程仍保守保留部分启动引脚。不能把旧款 ESP32 的“某组引脚只能输入”规则直接套到 S3，也不能将保留引脚当作任意可用输出。ADC 只支持对应模拟通道，纯数字引脚不能通过软件变成 ADC。

普通 GPIO 的 `PIN` 在脚本中指定。舵机映射会保存，换线遵循：进入维护并确认 → 断电 → 改线 → 上电查询最新配置 → 保存新映射 → 核对供电与校准 → 退出维护 → 显式移动。`07_servo.py` 是已接线后的动作示例，运行即表示已完成前置检查，不可在动作期间插拔杜邦线。

07 会保留名为 test 的舵机映射；之后若要将该信号脚改用于 GPIO/PWM，先检查配置，必要时运行 08 清除**全部**舵机映射。信号释放不切断舵机电源。

## 6 固件可以更换吗

可以。开发板不需要永久固定某个商品型号，但固件必须与芯片、Flash/PSRAM、USB 接口及板载灯接线匹配。当前构建基线是 ESP32-S3、16MB Flash、8MB OPI PSRAM、Arduino-ESP32 3.3.12、ArduinoJson 7.4.3。更小存储或不同 PSRAM 形式须调整构建并验证，不能直接套用当前镜像。

可以刷回原 AI 固件或其他系统；本 SDK 只兼容 `ai-maker-s3` 协议 v1。先前 `ai-maker-led-diagnostic` 和旧 AI 项目均不是这个协议。换固件后应先查询家族与能力，不以串口能打开判断协议兼容。

只编译、不烧录：

```powershell
.\firmware\build.ps1                                      # 默认原生USB / RGB48
.\firmware\build.ps1 -Transport uart                      # USB转UART口
.\firmware\build.ps1 -Transport native-usb -BuiltinRgbPin 38
```

修改GPIO、舵机和屏幕SPI/BLK映射不需要重新编译固件；更换RGB板型配置目前需要明确构建。麦克风/功放I²S信号映射仍待后续驱动接入。

## 7 完成范围与接线验收

本次交付是可编译、可通过电脑短脚本控制的**板级基础版本**。GPIO、ADC、PWM 和舵机的软件路径已验证；外部设备实际接线、电平、波形、校准及负载测试留给本次后续实测。

屏幕已在V0.3接入，支持ST7735S/ST7789、可保存的SPI信号、中文与图形；GPIO背光会使用一个普通PWM通道。麦克风、功放、SD与学生网页上传仍未接入，能力声明为false，调用会明确报不支持。后续需独立完成I²S、存储和网页宿主，AI服务器不在当前工程范围。

进阶测试仍保留在 `tests/hardware/`，需要显式参数并生成报告；学员优先使用 `tests/quick/`。两类脚本职责不同，均不会自行刷写固件。
