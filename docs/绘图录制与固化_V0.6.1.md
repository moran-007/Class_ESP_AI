# 像Turtle涂色一样：开始、结束，再固化

需要 **Python SDK0.6.1**；开发板继续使用已验证的 **0.6.0固件**。这是电脑端的录制功能，没有增加板端协议或重新烧录要求。GitHub0.5.0旧安装包不支持。

## 最短用法

先配置/启动外设，然后开始录制；原来熟悉的robot.display操作可以继续使用：

```python
from ai_robot import Robot

with Robot(port="COM5") as robot:
    robot.display.set(panel="st7735s_128x160", SCL=4, SDA=5,
                      CS=15, DC=7, RES=6, BLK=16, rotation=1)
    robot.start()

    robot.program.begin()
    robot.display.clear()
    robot.display.text("你好，创客！", x=8, y=8)
    robot.wait(3)
    robot.program.end()

    robot.program.save(loop=True, autostart=True)
```

直接复制运行的两页示例见 [15_screen_record.py](../examples/portable/15_screen_record.py)，对应用户的中英文、矩形和线段示例。默认接线为4/5/15/7/6/16；按实际IO和屏幕型号修改。

| 调用 | 发生什么 |
|---|---|
| 屏幕/舵机set及start | 完成静态映射和初始化，放在录制开始前；GPIO/PWM的set要放录制块内 |
| `robot.program.begin()` | 快照当前外设配置，开始记录；不开第二个串口，不上传固化内容 |
| `robot.display.clear/text/rect/line/...` | 立即显示，同时将支持的成功动作记录为Program步骤 |
| `robot.wait(seconds)` | 预览时实际等待，成功完成后也记录同样的板端等待 |
| `robot.program.end()` | 结束并返回独立Program；此时还没有保存到Flash |
| `robot.program.save(loop=True, autostart=True)` | 使用最近一次成功end的快照保存；下次重启自动运行 |
| `robot.program.cancel()` | 丢弃进行中的录制及已end的隐式save快照；不清屏、不撤回已预览动作、不删除板端已有流程 |

## 两种固化写法共存

原来的离线Program构建方式继续支持；它只收集步骤，不需要按等待时长预览：

```python
from ai_robot import Program, Robot

flow = Program()
flow.led.color("red")
flow.wait(1)
with Robot(port="COM5") as robot:
    robot.program.save(flow, loop=True, autostart=True)
```

begin/end写法适合边运行边看画面，Program写法适合快速生成流程。需要把录制结果交给另一连接或进一步处理时，显式保存end返回值：

```python
# 同一robot已配置、start并开始录制。
flow = robot.program.end()
robot.program.save(flow, loop=True, autostart=True)
```

end返回值和管理器保留的隐式save快照彼此独立。下一次begin开始新一轮，会使旧的隐式快照失效；不能在新一轮录制失败后误保存旧内容。save也可以始终显式传Program。

## 录制范围与错误处理

只录制已有Program允许的成功动作：板载RGB、GPIO模式/写入/释放、PWM、舵机动作、屏幕基本绘制及等待。第一次屏幕绘制会为回放补上display.begin步骤；clear对应保存的fill。配置快照在begin时确定，不通过录制过程中的set改变接线。

begin不是截图，也不快照当前GPIO/PWM模式或屏幕像素。屏幕/舵机映射的set和robot.start放begin前；GPIO/PWM的set必须放begin内，才能连同write一起保存。屏幕应在块内先clear/fill再重画完整内容。只记录robot.wait的显式等待，不记录print、time.sleep或电脑计算/用户停顿耗时。robot.stop始终可用，会放弃进行中录制并发送停止动作；已经end的快照仍可显式或隐式保存。

以下不属于录制能力：图片/bitmap、Turtle窗口、音频、页面管理、维护/配置更改、任意Python函数。需要保存Turtle绘制结果为离线图片是另一项能力，本接口不假装支持。普通Python的for会在电脑执行并产生实际步骤；它不是把Python源码/循环语法装到ESP32。板端动态判断仍用Program.when_digital/when_analog，录制时不允许gpio.read/adc.read作为动态条件。

状态查询和心跳不录入。录制时save/clear/start等程序管理动作要求先end或cancel。无begin不能end，不能嵌套begin，空录制不能固化。程序大小和节点限制仍为3072个UTF8字节、64个源节点、4层条件；等待每次最多60秒，0秒不增加步骤。

支持的拟录制步骤会在发送前做本地模型检查；设备拒绝、超时或等待失败时，本轮不能假装成功固化。动作不会自动重发。cancel不能撤销已经发生的显示或机械动作；关闭Robot会放弃未完成的录制并按正常会话规则停止输出。

## 保存、清除和最终状态

保存不会立刻开始独立回放，RESET或重新接电后按autostart策略执行。想当前连接试跑时，在save后显式program.start并保持会话；电脑下一次连接会接管停止。清除仍用原来的接口：

```python
from ai_robot import Robot

with Robot(port="COM5") as robot:
    robot.program.clear()
```

它保留屏幕/舵机配置和页面模板。原先启用的默认页会在关闭会话后恢复。相关实机清除流程见 [屏幕固化测试](屏幕固化测试与清除恢复_V0.6.md)。

SDK0.6.1的回归、安装包与验证边界见 [验证记录](verification.md)；本轮不自动更新GitHub发布，也不覆盖用户的tests/quick/screen_text.py。

## 页面1/页面2与变化数字

录制两次clear和绘图，是两段按顺序执行的画面，不会自动产生page1/page2标识。只需循环展示固定画面时，录制这些步骤就够了。

要按名字切页并刷新数字，使用已有JSON页面模板：页面有ID，文本控件也有ID。`pages.show`的参数是页面ID，`pages.text`的参数是当前页面中的控件ID。以已保存的示例模板为例：

```python
# 同一robot已配置屏幕并启动，且已上传示例page_demo.json。
robot.pages.show("home")
for count in range(10):
    robot.pages.text("status", "次数：" + str(count))
    robot.wait(0.5)
robot.pages.show("status")
robot.pages.text("status", "新的状态")
```

这里数字更新是临时运行数据，不需要每次重传模板或写Flash；切换页面后按当前应用状态重新更新控件。页面ID和控件ID是不同层次，示例中两个页面各有status控件，更新只作用于当前显示页。

pages操作不属于本版begin/end固化白名单，上例应在录制块外执行。普通Python计数依赖电脑保持运行；录制静态1、2、3不会变成断开电脑后持续计算的变量。板端自动计数、传感器数值绑定到文本和按名离线切页需要另外扩展执行器，本版不假装支持。
