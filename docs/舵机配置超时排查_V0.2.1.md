# SG90 舵机配置超时：V0.2.1 修复记录

日期：2026-11-08。现象：用户运行 07，设置 test 舵机、GPIO14、90°，在 `r5 (config.apply)` 超时，尚未执行 `servo.move`。芯片实机固件为 ai-maker-s3 0.2.0，通路是 COM5 原生 USB。只读状态显示维护中、配置为空、无存储错误。

## 原因与证据

V0.2.0 在 `ai_maker_s3.ino` 中把 `Serial.setRxBufferSize(8192)` 包在 `!ARDUINO_USB_CDC_ON_BOOT` 条件里，仅 UART 生效。Arduino-ESP32 3.3.12 的 `HWCDC::begin()` 未预设时默认建立 256 字节队列；接收 ISR 遇到队列满后退出，剩余字节不会进入应用。

因此 SDK 一次发出的较长 JSON 配置请求可能缺失尾部，无法形成匹配的有效请求。增加 Python 超时无法恢复丢失的字节。这不是已证明的 SG90 驱动、电源或 GPIO14 故障，错误发生时程序还没走到动作阶段。

在同一旧固件上先用只读 device.info 加填充验证：总长度160、240、256字节单次写入通过，280、360、700字节没有匹配回执；360、700字节改为64字节分段并间隔3毫秒发送后通过。随后永久回归脚本按 JSON 本体长度（另加一个换行）验证：160、255通过，256、257、384、768、2048、4096失败。长度差一字节来自是否计入换行，结果均指向256字节接收队列。

查询填充探针证明匹配的 JSON 请求/响应能否完成，不是逐字节校验和证明。因此另对真实配置执行完整保存、读回与内容比对。

## 修复

- 固件升为0.2.1，UART和HWCDC都在 `Serial.begin()` 之前设置8192字节RX缓冲，协议上限仍为4096字节JSON加换行。
- Python SDK仍为0.2.0，协议v1不变，没有增加动作自动重发。
- 公共示例连接模块将请求超时与协议不兼容区分提示，不再根据一次超时断言固件不匹配。
- 保留用户修改的02、04、07等脚本。新增 `tests/quick/servo_sg90.py`，信号默认GPIO14，1000～2000µs配置，依次60/90/120/90，每次一秒。它仍须按实物供电、共地、接线与校准，不能通过回执宣称实际到位。
