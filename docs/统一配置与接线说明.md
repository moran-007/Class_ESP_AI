# 可选统一配置与接线说明

当前推荐学员直接在Python代码中配置串口和IO，见 [代码内配置与最小示例](代码内配置与最小示例.md)。本文保留进阶集中配置方式，配套示例为 `tests/guide_shared/`。

适用：当前 `ai-maker-s3` 固件V0.4.0、SDK V0.4.1、ESP32-S3 N16R8/RGB48参考板。此轮只整理电脑端配置、课程入口和说明，ESP32固件无需再刷写。

## 1. 最短使用流程

1. 首次双击 `安装Python环境.cmd`。需要Python3.11+、pyserial；图片/Turtle需要Pillow，安装脚本已包括。标准Turtle及配置窗口还需要Python自带Tcl/Tk。
2. 双击 `配置硬件.cmd`：串口页选择 `COM5` 或保留 `AUTO`；在对应页填写GPIO、屏幕型号、舵机校准。点保存。
3. 完成供电与接线后，直接运行 `tests/guide_shared/` 的一个短Python文件。主菜单现运行代码内配置版，参数在各文件中填写。
4. 改配置后关闭并重新运行示例。正在运行的程序不会热加载新接线；保存配置本身不会连接USB或改变板上输出。

省略显式串口/IO的兼容课堂入口读取同一个 `config/hardware.json`。页面编辑器启动时也用它预填串口及屏幕参数；连接板子后显示板上实际保存映射。编辑器内“保存屏幕接线”只写开发板，不自动修改电脑文件；想让其他示例跟随改线，使用配置窗口同步修改。

`Robot(port=...)` 是可独立安装的SDK基础接口，显式参数始终有效；不会隐式读取这个项目文件。`classroom.connect()` 才是读取本项目配置的便捷入口。

## 2. 字段与需求

| 区域/字段 | 默认值 | 意义与配置要求 |
|---|---|---|
| schema_version | 1 | 本地配置格式；不要修改 |
| connection.port | AUTO | 唯一USB串口自动选择；多个USB设备时明确COM5等名称。GUI刷新只枚举，不探测串口协议 |
| pins.led | 12 | 普通外接LED输出脚；不是板载RGB脚；LED需要合适的限流电阻 |
| pins.button | 2 | 按钮接该GPIO和GND，使用内部上拉；按下0、松开1 |
| pins.adc | 1 | 模拟输入，当前选GPIO1～20中非保留脚；原始12bit计数，未校准电压 |
| pins.pwm | 12 | 调光输出预设，固定1kHz；与led同脚可分别运行 |
| servo.name | test | ASCII字母开头，字母数字下划线，最多24字符；板端逻辑设备名 |
| servo.pin | 14 | SG90信号；匹配的独立供电、与板共地，不能GPIO供电 |
| servo.min_angle / max_angle | 30 / 150 | 指令允许角度，0～180严格递增；不改变脉宽按0～180映射的规则 |
| servo.min_pulse_us / max_pulse_us | 1000 / 2000 | 当前SG90已验证的实验预设；需按实际舵机校准，不代表任意型号通用值 |
| display.panel | st7735s_128x160 | 还支持st7789_240x320、st7789_240x240 |
| display.sck / mosi | 4 / 5 | SPI时钟及数据；屏幕SDA通常对应MOSI，不是I²C |
| display.cs / dc / rst | 15 / 7 / 6 | 片选、命令/数据、复位；按真实连接填写，不能重复 |
| display.backlight | 16 | BLK接GPIO时填实际脚；7针无BLK或BLK固定电源时填-1 |
| display.rotation | 1 | 0/2竖屏，1/3横屏；方屏仍可旋转 |
| display.invert | false | 明确反相；ST7735通常false，ST7789通常true，按实际颜色校验 |
| display.brightness | 60 | 有GPIO背光0～100%，无GPIO背光必须100 |

没有自动确定屏幕控制器、舵机型号或杜邦线接在哪里的能力。普通信号可换GPIO，但实际接线、配置和板级可用能力必须一致。

## 3. GPIO能力和占用

数字为板上标注GPIO/IO号，不是排针顺序。当前固件保守保留：0、3、19、20、26～37、43、44、45、46、48；22～25不存在于本profile可分配范围。GPIO48用于已确认的板载RGB，不通过本地配置改成其他脚。换到不同开发板应核对硬件描述和固件，不能把本表当作所有S3的物理能力表。

`robot.list_pins()` 中 `input/output/adc` 是当前固件暴露能力，`reserved/owner` 表示系统或已保存映射占用。当前普通可分配脚均可作数字输入/输出，没有另外开放“仅输入脚”；46被保留，未对课程开放。ADC只是部分脚支持。屏幕信号需要可输出GPIO；当前所有SPI信号可运行时配置。

屏幕内部引脚互斥；舵机信号不能与屏幕重叠。GUI本地校验拒绝这些冲突，但板上可能保存其他舵机映射，因此板端 `config.apply` 的最终检查仍必要。普通LED/按钮/ADC/PWM字段是不同实验预设，允许复用；同时运行时自行确保不冲突，按钮控制LED示例需要两个不同脚。被保存为屏幕/舵机的GPIO，即使当前不在输出，也不等于空闲。

关闭/释放输出不会删除保存映射。删除屏幕使用 `display.unconfigure()`；删除舵机通过维护下的 `config.apply()` 修改servo列表（旧 `08_clear_servos.py` 会删除全部舵机）。不要为腾出一只脚误删其他外设配置。

## 4. 电脑配置与板上配置

| 操作 | 电脑hardware.json | 板端持久配置 | 是否开始硬件输出 |
|---|---|---|---|
| 配置窗口保存 | 修改，旧内容备份hardware.json.bak | 不变 | 否 |
| connect() | 读取串口，启动SDK会话 | 不改接线 | 不自动启动外设；已运行默认页让出屏幕 |
| connect_screen() | 读取display | 保存屏幕映射 | 明确退出维护并begin，随后允许绘图 |
| servo.configure(**SERVO) | 不变 | 保存同名舵机映射，保留其他映射 | 停止运行输出、进入并保持维护，不移动 |
| maintenance.exit() | 不变 | 保存退出维护状态 | 本身不恢复舵机动作 |
| 页面编辑器保存接线 | 不变 | 保存表单屏幕映射 | 停止当前输出并退出维护；之后显示页才初始化 |

统一配置中的外设预设不是“所有外设一起启用”。每个例子只操作需要的接口。换线建议：用SDK进入维护并确认 → 断电换线 → 修改电脑配置 → 上电 → 运行对应实验应用配置并显式测试。

配置格式、字段名、类型、范围、重复字段都会检查；无效文件报错，不静默回退默认GPIO。GUI保存使用同目录临时文件替换，之前版本保存为 `.json.bak`；它是电脑文件备份，不是ESP32 NVS备份。

## 5. 旧代码与迁移

迁移前的 `tests/quick/settings.py`、`_screen_settings.py` 原文逐字节保存在 `config/legacy/`。它们原有有效值AUTO、ST7735S、4/5/15/7/6、BLK16、旋转1、自动反相false和自动亮度60，已迁入统一JSON。

旧文件现在只作兼容读取入口；以后不要再在旧入口写配置值。历史文档提到修改settings或_screen_settings时，均以本说明的新入口为准。

`tests/quick/01`～`08`、你手写的按钮/屏幕/Turtle绘图内容保持原样；这些旧文件自己写的PIN仍然优先用于自己的代码，不能自动被统一预设替换。要免改PIN，请使用 `tests/guide/` 新示例，或改成 `from _board import PINS` 再使用 `PINS['led']` 等值。只改串口时，旧公共连接也会跟随统一配置。
