# MicroPython 与 Class_ESP_AI 当前方案

日期：2026-11-14。本项目0.6.0采用“电脑CPython SDK + ESP32 C++固件 + 可保存的受限硬件流程”，没有改成MicroPython。本篇解释技术取舍，不代表已经完成MicroPython移植或对比实测。

## 1. 最主要的区别是 Python 在哪里运行

当前普通Python程序运行在电脑，`Robot`通过USB调用板端C++驱动。新增`Program`把允许的硬件步骤序列化，交给板端执行器保存和运行；ESP32没有因此得到任意Python解释器。

MicroPython把Python运行环境放到微控制器内，可以将应用保存为板内文件。其开机流程支持用户`boot.py`初始化和`main.py`应用入口；并非所有复位/工具交互场景都会等同冷启动。[官方启动说明](https://docs.micropython.org/en/latest/reference/reset_boot.html)

| 比较项 | 当前方案 | MicroPython方案 |
|---|---|---|
| 普通教学代码位置 | 电脑CPython，USB指令到C++固件 | 主要Python应用直接在板内 |
| 离线/独立供电 | 0.6起保存的Program白名单流程可执行；普通电脑Python仍需电脑 | 保存到板内的兼容Python应用可以独立执行 |
| 语言表达 | 电脑侧可用完整已安装CPython生态；固化侧是明确受限的流程 | 板端支持Python的一个实现和子集，不能假设所有CPython语法/行为/库都相同 |
| 更新学员程序 | 在线脚本直接改；固化流程调用save，无需每次重刷完整固件 | 修改/传输板内Python文件；固件升级另外处理 |
| 已有外设资产 | 复用当前已接入的Arduino/ESP-IDF驱动及USB协议 | 需要核对所用port、版本及驱动；当前C++库/ai_robot不能直接视为MicroPython模块 |
| 电脑窗口与文件 | 能用标准库Turtle、Pillow、电脑文件/工具；这些不自动进入固化程序 | 板内没有电脑桌面/Tk窗口，需要改为设备显示或由电脑配合 |
| 资源与时序 | 板端C++负责硬件；当前流程执行按tick推进，等待不阻塞USB处理 | Python对象、解释器和内存回收参与板端运行，需要结合应用管理资源与时序 |
| 学习体验 | API统一，设备范围明确；更自由的离线语法要继续扩展执行器 | 更接近“写Python就跑在板上”；需要学习板端模块、文件和资源边界 |
| 维护重点 | 维护SDK、协议、C++固件以及固化指令合同 | 维护MicroPython固件/port、Python驱动、SDK适配和板内应用 |

MicroPython并非电脑CPython的完全等价替代，官方列出了语言、类型、模块等差异。[官方差异清单](https://docs.micropython.org/en/latest/genrst/index.html)

## 2. 优点与限制分别落在哪里

**当前方案适合本项目已有教学内容。** 原屏幕、中文、RGB、SG90、I²S录放、页面模型和Turtle发送链路可以继续用；电脑侧无需限制成板内Python模块集合。新增Program后，按钮判断、RGB、GPIO、PWM、舵机和基本屏幕流程可独立供电运行。

代价是离线流程表达需要明确扩展：不能保存任意Python函数、`while`、`if`、导入库或电脑文件操作。当前离线条件用`when_digital/when_analog`构建，循环由保存策略选择；要增加新的固化动作，通常需同时维护SDK序列化、协议验证和板端执行。

**MicroPython更适合把较自由的Python应用直接交给开发板执行。** 板内变量、函数、循环及条件可以按其支持的语言来写；应用文件更新与固件更新是分开的。代价是现有工程不能仅换固件名字：需要移植/选择屏幕、中文、舵机、音频等驱动，重新适配当前库及教学示例，并在目标板验证资源占用和行为。

不能把“MicroPython”理解为“不支持PWM、ADC或I²S”。官方ESP32快速参考提供相关硬件能力，但可用性、细节和限制要按芯片变体、port、固件版本和具体驱动核对。[官方ESP32参考](https://docs.micropython.org/en/latest/esp32/quickref.html)

本项目没有执行两种方案的同任务性能基准，因此不提供“快几倍”或确定帧率/音频质量结论；电脑参与程度、USB传输、屏幕驱动、DMA、内存分配和应用结构都会影响结果。

## 3. 推荐方向

针对当前目标，先保留C++固件并增加固化函数，复用现有能力。首次使用固化功能需要升级支持0.6的教学固件；以后修改受支持的流程，只上传Program，无需每次重刷固件。

如果后续课堂目标变成“学生在板内自由写Python函数和任意兼容语言流程”，可把MicroPython作为独立固件路线评估；不应对当前`robot.program.save(...)`宣称任意Python序列化能力。

两种方式都允许以后继续改代码，关键是明确更新的是电脑程序、板内保存流程/文件，还是固件本体。固化本身不意味着把板锁死。[Program使用说明](开发指南.md#15-程序固化通电后独立运行)

上述官方链接使用latest文档，可能描述开发分支；实际移植时应选定具体发布版本并按对应文档验证。
