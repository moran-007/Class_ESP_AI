# Class_ESP_AI：Python 编程与开发指南

当前 SDK 0.8.3、教学固件 0.8.0，导入名 `ai_robot`。在 [v0.8.3 教学预发布](https://github.com/moran-007/Class_ESP_AI/releases/tag/v0.8.3) 下载源码、SDK 和固件。**本文件是长期维护的主教程。** 完整函数见 [SDK 手册](SDK函数说明与示例_V0.6.md)，实机状态见 [验证记录](verification.md)。

## 1. 先理解程序在哪里运行

学员写的 Python 在电脑运行，通过 USB 向 ESP32 发指令；ESP32 运行的是 Arduino/C++ 教学固件。安装 SDK 不会烧录开发板，运行一个新的 Python 文件也不会替换固件。

| 层次 | 内容 | 什么时候改变 |
|---|---|---|
| 学员 Python 程序 | 接线参数、绘图、动作和流程 | 每次实验可改 |
| Python SDK | `Robot`、屏幕/音频等公共函数 | 安装或升级 wheel |
| ESP32 固件 | GPIO、SPI、I²S、舵机驱动及 USB 协议 | 增加板端能力/修复板端问题时烧录 |
| 板端保存数据 | 舵机/屏幕映射及默认页面等 | 明确调用相应配置/保存接口 |

当前没有 AI 服务器、识别、聊天或 TTS；音频 URL 接口只接收明确提供的音频。标准库 Turtle 在电脑画图，板端接收图像。0.6新增Program将白名单硬件流程保存在板端，独立供电执行；它不把电脑Python解释器或任意函数搬到板上，详见第15节。

## 2. 安装及第一次运行

在 Windows 安装 Python 3.11+ 后，双击项目根目录的 [安装Python环境.cmd](../安装Python环境.cmd)。它在根目录创建唯一的 `.venv`，一次安装 SDK 0.8.3、串口和绘图依赖；健康的环境重复运行时会直接复用。源码安装后，编辑本项目的 SDK 文件即可在下次运行看到修改，通常不必重复安装。示例和配置工具共用这个环境。

VS Code 打开 `ai_maker` 文件夹；若曾选过其他解释器，在「Python: Select Interpreter」里改成根目录 `.venv/Scripts/python.exe`，以后直接用「Run Python File」。也可选择「AI 小创客：运行当前 Python 文件」调试配置。

普通固化最低需 0.6 固件，计数器最低需 0.7 固件，配网需声明 `wifi_provisioning` 的 0.8 固件。只升级 SDK 不改变开发板固件。GitHub 旧 0.5 附件不具备这些新能力。只有在另一台电脑单独分发脚本、不带项目源码时，才需要在那台电脑的目标 Python 环境里安装对应 wheel：

```powershell
python -m pip install ./ai_maker_robot-0.8.3-py3-none-any.whl
```

图片/Turtle 功能另装可选依赖，Python 安装时需带 Tcl/Tk：

```powershell
python -m pip install "./ai_maker_robot-0.8.3-py3-none-any.whl[drawing]"
```

创建自己的 `main.py`，不要命名为 `ai_robot.py`、`serial.py` 或 `turtle.py`，避免遮蔽同名库：

```python
from ai_robot import Robot

with Robot(port="COM5") as robot:
    print(robot.get_info())
```

`port` 是这台电脑的实际串口；COM5 只是示例。`Robot` 创建时连接并握手，不移动舵机。`with` 结束时关闭连接。这段只读信息适合作为第一个测试。IDE 选择安装了 SDK 的 Python 解释器，不需要 `_board.py`。另一台电脑只需重新安装 wheel 和依赖，详见 [跨电脑安装](跨电脑安装与直接导入_V0.5.md)。

## 3. 推荐的程序结构与多外设顺序

不强制使用 with，也可以用 try/finally。同一个串口只创建一个 Robot，屏幕、舵机和音频都挂在它下面：

```python
from ai_robot import Robot

robot = Robot(port="COM5")
try:
    robot.servo.set(pin=14, name="arm")
    robot.start()
    robot.servo.move("arm", 90)
    robot.wait(3)
finally:
    robot.close()
```

此程序运行会驱动舵机；先完成供电、共地，首次卸下连杆。`set` 保存舵机映射且保持维护状态，`start` 退出维护并启动本连接请求的屏幕/音频，`move` 才发出角度动作。`close` 释放输出，不会切断模块电源，不保证舵机回90°。

组合顺序固定为：**audio/display/servo.set → robot.start → digital/analog/pwm.set → 动作**。前一组是外设映射；后一组立即设置 GPIO 模式，维护状态中不能执行。不要在每帧绘图或动作循环中重复 set；配置会停止已有运行输出。

例子中 `pin=14`、`sck=4` 是信号对应的 GPIO，不是排针上的第几脚。系统保留脚、已占用脚会被拒绝。调用 `robot.list_pins()` 查看能力、`reserved` 和 `owner`；能输出不代表当前空闲。屏幕丝印别名见 [对应表](set接口_丝印对照与刷新帧率.md)。

## 4. 板载 RGB 与数字输入/输出

RGB 示例 [09_rgb.py](../examples/portable/09_rgb.py)，只需 USB：

```python
from ai_robot import Robot

with Robot(port="COM5") as robot:
    robot.start()
    robot.led.set(red=8, green=16, blue=3)
    robot.wait(2)
```

这是板载 WS2812 的数据控制，每通道0～32；`led.color("yellow")` 是命名色，`led.off()` 熄灭。当前发布构建的 RGB 在 GPIO48；普通 GPIO 常高不能代替 RGB 数据。

外接按钮接 GPIO2 与 GND，外接 LED 通过匹配限流电阻接 GPIO12 与 GND。以下按下点亮，松开熄灭；LED 极性或接到3.3V的接法会改变点亮逻辑：

```python
from ai_robot import Robot

with Robot(port="COM5") as robot:
    robot.start()
    robot.digital.set(pin=2, mode="input_pullup")
    robot.digital.set(pin=12, mode="output")
    for _ in range(20):
        pressed = robot.digital.read(2) == 0
        robot.digital.write(12, int(pressed))
        robot.wait(0.1)
```

上拉输入松开读1、接地按下读0；输出用 `int(pressed)` 转为0/1。`input`、`input_pullup`、`input_pulldown`、`output` 是四种数字模式。输入悬空会不稳定。ESP32 信号不能直接接5V。

## 5. 模拟输入与 PWM

完整实验见 [07_io_types.py](../examples/portable/07_io_types.py)。下例分别设置 ADC 与 PWM，需要外部模拟信号和 PWM 实验负载：

```python
from ai_robot import Robot

with Robot(port="COM5") as robot:
    robot.start()
    robot.analog.set(pin=1)
    robot.pwm.set(pin=17)
    print(robot.analog.read(1))
    robot.pwm.write(17, 25)
    robot.wait(3)
```

ADC 读原始12bit计数0～4095，不是校准后的伏特。GPIO1～20是 ADC 候选，仍受保留脚/资源占用限制。PWM 固定1kHz，占空比整数0～100%，适合本实验的 LED 调光；GPIO不能直接驱动电机等大电流负载。PWM 不是真正连续模拟电压，`robot.analog.write(...)` 明确报不支持 DAC。旧 `gpio/adc/pwm` 调用继续兼容。

## 6. SG90 舵机

[10_servo.py](../examples/portable/10_servo.py) 展示单舵机，两项主要配置为信号脚与逻辑名：

```python
from ai_robot import Robot

with Robot(port="COM5") as robot:
    robot.servo.set(pin=14, name="arm", min_angle=30, max_angle=150)
    robot.start()
    robot.servo.move("arm", 90)
    robot.wait(3)
```

`set` 的课堂脉宽默认1000～2000µs，逻辑角度限制默认30～150。旧 `configure` 默认脉宽500～2500µs，两者不能混为同一默认值。根据实际舵机校准；当前没有真实位置反馈。可以用不同名称/引脚配置多个舵机，最多4个；独立匹配供电且与 ESP32 共地，不能从信号 GPIO 给舵机供电。

程序退出后停止 PWM 是会话清理，不是把信号口永久锁死。希望长期控制时保持 Python 程序运行；下一程序可以重新配置。希望脱离电脑运行完整行为，需要另行开发板端逻辑，不是把当前 Python 文件拷进去。

## 7. SPI 屏幕：文字、图形与图片

可复制 [11_display.py](../examples/portable/11_display.py)：

```python
from ai_robot import Robot

with Robot(port="COM5") as robot:
    robot.display.set(panel="st7735s_128x160", SCL=4, SDA=5,
                      CS=15, DC=7, RES=6, BLK=16, rotation=1)
    robot.start()
    robot.display.fill("black")
    robot.display.text("你好，创客！", x=8, y=8)
    robot.display.rect(8, 40, 80, 20, color=(55, 88, 99), filled=True)
    robot.wait(10)
```

`panel` 决定初始化序列与尺寸；支持 ST7735S128×160、ST7789240×320/240×240。改型号同时核对实际分辨率。SCL 在这里是 SPI 时钟，SDA 是 MOSI，不表示 I²C；RES 是复位，BLK 是可选背光。信号都可以按允许 IO 自定义。未接可控背光时填 `backlight=-1`；供电脚不填 IO 参数。

`rotation=1` 时本 ST7735 的有效画面为160×128，坐标不能超界。屏幕颜色三元组是0～255，与板载 RGB 的0～32不同。中文使用内置字库，不覆盖任意 Unicode 字符。

```python
# 已 set/start 的同一 robot 上使用；需要 Pillow 和自己的图片文件。
result = robot.display.image("picture.png", fit="contain")
print(result["transfer_seconds"])
```

`contain` 保留整图并补边，`cover` 居中裁剪填满。`display.set(..., fps=10)` 只是电脑端整屏图片发送帧开始上限，不是面板刷新率，也不保证达到10帧。文字/图形 API 不受此上限限制。

## 8. 页面模板与默认页面

页面是受约束的 JSON 布局模型，不执行学员上传的 JavaScript/HTML。电脑网页编辑器可以编辑/导入导出页面和图标，保存给板端；详见 [页面与Turtle说明](页面编辑器与Turtle_V0.4.md)。

在**已经配置屏幕并 start 的同一 robot**上使用，示例文件尺寸为160×128：

```python
robot.pages.upload("page_demo.json")
robot.pages.show("home")
robot.pages.text("status", "Python更新成功")
print(robot.pages.info())
```

把仓库 [page_demo.json](../examples/pages/page_demo.json) 放到程序工作目录。`upload` 保存模板但不启用开机显示；`show` 显示页面；`text` 只临时更新当前控件，不回写模板。明确需要关闭 Python/复位恢复此页时再执行 `robot.pages.startup("home", enabled=True)`；只影响屏幕，不恢复舵机动作。`pages.download()` 读回模板，`pages.clear()` 清空且保持维护。完整大小/控件限制见 [页面协议](../protocols/pages-v1.md)。

## 9. Turtle 画好再发送

[08_turtle.py](../examples/portable/08_turtle.py) 使用标准库窗口；发送辅助也在安装包内：

```python
import turtle
from ai_robot.turtle import finish

screen = turtle.Screen()
pen = turtle.Turtle()
pen.circle(60)
pen.hideturtle()
finish(screen, port="COM5", panel="st7735s_128x160",
       SCL=4, SDA=5, CS=15, DC=7, RES=6, BLK=16)
```

这个写法先画图，点击“发送”或 Enter 时才连接。若开头已经创建并配置了 Robot，则结尾使用 `finish(screen, robot=robot)`，不要再传另一组 COM/IO，也不要为同一端口再开连接。关闭 Turtle 窗口会关闭它接管的整条连接，包括同一 Robot 的其他输出。发送的是临时像素画面，不替换默认模板。电脑窗口要保持可见，不能最小化后捕获。

## 10. INMP441 收音

先单独运行 [02_audio_record.py](../examples/portable/02_audio_record.py)：

```python
from ai_robot import Robot

with Robot(port="COM5") as robot:
    robot.audio.set(bclk=42, ws=41, din=21, dout=-1, sd=-1)
    robot.start()
    robot.wait(0.2)
    clip = robot.audio.record(seconds=3)
    clip.to_wav("recording.wav")
    print(clip.levels)
```

麦克风3.3V供电并共地：BCLK/SCK 是时钟，WS 是声道时钟，麦克风 SD 是数据，接 ESP32 的 `din`。L/R 接地选 left；接高电平时填 `mic_channel="right"`。`dout=-1, sd=-1` 关闭功放方向。短等待仅帮助上电稳定，不构成具体模块启动时间保证。

录音返回 `AudioClip`；WAV 保存到当前工作目录。`all_zero` 帮助排查无数据，`clipped_samples` 提示削顶，但非零不等于真实人声质量合格。此版本一次录音最多30秒，无重采样或 MP3 编解码。

## 11. MAX98357A 功放、本地与 URL 音频

先运行 [03_audio_tone.py](../examples/portable/03_audio_tone.py) 的低幅测试音：

```python
from ai_robot import Robot, AudioClip

with Robot(port="COM5") as robot:
    robot.audio.set(bclk=42, ws=41, din=-1, dout=40, sd=39, volume=20)
    robot.start()
    robot.audio.play(AudioClip.tone(frequency=440, seconds=1, volume=0.1))
```

功放 BCLK/LRC 对应 bclk/ws，DIN 接 ESP32 `dout`，SD/EN 是关断控制，**与麦克风 SD 的数据含义不同**。功放匹配供电并共地，扬声器接功放输出，不能把 BTL 任一输出端接 GND。`volume=20` 是播放软件增益百分比，不是麦克风增益；tone 的 volume 是生成信号的幅度。

两个模块可共用一组 BCLK/WS，数据方向独立，当前采用“录完再播”的半双工：[04_audio_echo.py](../examples/portable/04_audio_echo.py)。停止录放用 `audio.stop()`，结束 I²S 硬件用 `release()`，需要释放映射让其他功能使用 IO 时用 `unconfigure()`。`sd=-1` 时软件不能保证功放硬件关断。

```python
# 同一 robot 已 set/start；文件或网址须由你明确提供。
robot.audio.play_file("recording.wav")
robot.audio.play_url("http://127.0.0.1:8000/recording.wav")
```

URL 示例要先在音频文件目录运行 `python -m http.server 8000 --bind 127.0.0.1`，SDK 不自动创建服务器。这里只是文件音频服务，不是 AI 服务器。对应短例为 [05](../examples/portable/05_audio_file.py)、[06](../examples/portable/06_audio_url.py)。

本地、收音、URL 都用同一个 `AudioClip`：**16000Hz、单声道、有符号16bit、小端 PCM**。WAV 只是文件容器，不能把 WAV 头当成 PCM 发给板端/未来服务。原始字节和元数据衔接示例：

```python
from ai_robot import AudioClip

clip = AudioClip.from_wav("recording.wav")
raw = clip.to_pcm()
metadata = clip.to_wire()
same = AudioClip.from_wire(raw, metadata)
```

裸 PCM URL 需要显式 format="pcm_s16le" 且用参数或响应头声明16000Hz/1声道。当前没有 ASR/TTS/对话 API、压缩音频解码或后台自动云请求。更多错误与格式限制见 [音频说明](数字模拟IO与音频测试_V0.5.md)。

## 12. 维护、故障与退出

| 现象/回执 | 先做什么 |
|---|---|
| ImportError/ModuleNotFoundError | 核对 IDE 解释器和 pip 安装目标；避免同名脚本遮蔽库 |
| COM 被占用 | 关闭自己运行的 Python/Turtle/串口监视器后重跑；不并行打开同一串口 |
| 不兼容固件/能力缺失 | 确认 ai-maker-s3 及版本；旧 AI 固件/白灯诊断固件不是教学固件 |
| PIN_RESERVED / RESOURCE_CONFLICT | 看 list_pins 的 reserved/owner，改允许的空闲 IO |
| MAINTENANCE_REQUIRED/维护状态错误 | 检查映射 set → start → 即时 GPIO set 的顺序 |
| RequestTimeout | 动作可能执行，不自动重发；先查看设备状态并排查连接 |
| 屏幕有回执但黑屏/音频有数据但无声 | 分别核对供电、信号、型号、背光/SD和声道；回执不等于物理效果 |

换线前先 `robot.maintenance.enter()` 确认，再断电换线；修改代码后上电配置、start。普通退出用 close；会话异常时6秒租约是最后清理保障，不是日常关闭替代品。维护标志、屏幕/舵机配置可持久化；音频映射只属于当前会话。

## 15. 程序固化：通电后独立运行

### 15.1 固化什么，第一次需要准备什么

固化是把支持的设备流程保存到ESP32 Flash，按开机策略独立执行。学员仍用Python编写，但`Program`构建的是步骤，不是把任意Python函数复制到板上。固化不会锁死板子，后续仍可连接电脑、保存新流程或运行普通在线程序。

固化至少需要兼容 0.6 功能的 SDK 和教学固件；旧 0.5 固件会明确报不支持。当前 v0.8.3 附件包含兼容的 SDK 和 0.8.0 固件。首次升级后，修改已支持的流程只需再次 `save()`，不用每次重刷。

| 模式 | 写法 | 执行位置 |
|---|---|---|
| 在线控制 | robot.led.color / robot.wait | 电脑发指令；需保持会话 |
| 构建待保存流程 | program.led.color / program.wait | 此刻只收集步骤，不驱动硬件、不睡眠 |
| 上传固化 | robot.program.save | 校验并保存，不立即运行 |
| 开机运行 | 保存时autostart=True或之后enable | 下次重启且非维护状态由板端执行 |

### 15.2 最短例子：开机红绿循环

可直接复制 [12_program_save.py](../examples/portable/12_program_save.py)，只使用板载RGB：

```python
from ai_robot import Program, Robot

program = Program()
program.led.color("red", brightness=8)
program.wait(1)
program.led.color("green", brightness=8)
program.wait(1)

with Robot(port="COM5") as robot:
    robot.program.save(program, loop=True, autostart=True)
```

运行这段先连接并保存，结束时不立即红绿循环。关闭程序后重启或重新接电，保存的流程才按开机策略循环；只给板供电即可，不需要电脑继续运行这个文件。`Program.wait(1)`被保存为板端等待步骤，和电脑的`time.sleep`不同。

save默认`loop=False, autostart=False`：前者表示执行到末尾释放输出，后者表示保存后不开机自动运行。例子明确把两项都设为True。即使开启autostart，save也不立即运行；需要当前连接立即试跑时显式调用`robot.program.start()`并保持连接，或按上述方式重新上电。

### 15.3 继续写新代码、停止和删除

```python
from ai_robot import Robot

with Robot(port="COM5") as robot:
    print(robot.program.info())
    robot.program.stop()
    # robot.program.disable()  # 保留流程，关闭下次开机自启。
    # robot.program.enable()   # 开启下次开机自启，不立即执行。
    # robot.program.clear()    # 确认需要删除时才调用。
```

创建Robot握手取得会话时会接管并停止固化流程。之后可用原来的在线接口；同一时刻不让固化执行器和在线动作争用输出。close默认不恢复固化，防止程序退出后突然再次动作；若enabled仍为True，下次重启继续按保存策略运行。[13_program_control.py](../examples/portable/13_program_control.py)默认只查看/停止，删除操作保留为注释。

`program.stop()`只停当前运行，不改变下次开机策略；`disable()`保留步骤但关闭自启；`clear()`删除步骤与开机策略。`enable()`不能启用一个不存在的流程。`start()`在当前会话运行已保存内容，必须非维护；当前会话close或租约到期会停止，不把它变成无主后台动作。

save/enable/disable/clear在SDK中先进入维护，成功后退出维护。任何一步失败都要看错误与`info()`，不要自动重复保存；程序可能已写入而退出维护失败，此时不会据此认定开机运行已准备完毕。

### 15.4 按钮、ADC条件和外设配置

按钮接GPIO2与GND，外接LED通过匹配限流电阻接GPIO12与GND；具体信号可在文件开头改。完整程序见 [14_program_button.py](../examples/portable/14_program_button.py)：

```python
from ai_robot import Program, Robot

pressed, released = Program(), Program()
pressed.digital.write(12, 1)
pressed.wait(0.05)
released.digital.write(12, 0)
released.wait(0.05)

program = Program()
program.digital.set(2, "input_pullup")
program.digital.set(12, "output")
program.when_digital(2, 0, then=pressed, otherwise=released)

with Robot(port="COM5") as robot:
    robot.program.save(program, loop=True, autostart=True)
```

`when_digital`在板端执行时读取状态，等于0时执行then，否则执行otherwise。上拉按钮接地按下读0。不能写`if program.digital.read(...)`，Program没有返回运行期读值的read接口；普通Python的if只在电脑构建程序时发生，不能自动转成板端条件。

ADC用`program.analog.set(pin)`，再用`program.when_analog(pin, ">=", 2000, then=high, otherwise=low)`；支持`< <= == != >= >`，比较的是0～4095原始计数。then必须是非空Program，otherwise可省略或为空Program。分支只能包含步骤，屏幕/舵机映射放在主Program中配置。

主程序用`program.servo.set(pin=14, name="arm")`和`program.servo.move("arm", 90)`；用`program.display.set(...)`配置屏幕后写text/fill/rect/line。屏幕set自动插入display.begin步骤，不需额外的robot.start。程序自己的屏幕/舵机快照临时生效，不覆盖原在线持久配置；结束后恢复映射不代表自动移动舵机。

### 15.5 支持范围、大小与验证

支持：板载RGB、数字模式/写入/释放、ADC条件、PWM、舵机、基本屏幕绘制与亮度、等待、条件分支及整个流程循环。先setup再使用IO；不完整的分支配置可能在运行时出错并停止。

不支持：任意Python函数/源码、用户自定义脚本解释器、录放音频、图片、Turtle窗口、云端请求或任意网页。电脑侧仍可自由使用在线SDK能力，但这些不能直接塞进Program。

紧凑UTF8 JSON最多3072字节，最多64个源步骤节点（含条件和所有分支），条件最多4层；每次wait为大于0且不超过60秒，板端按tick推进，不用长时间阻塞USB循环。到末尾或故障会停止并清理输出；清理失败单独报告，不能当作实物已正常停止。`physical_verified=False`仍表示没有真实位置/光学反馈。

0.6固化已完成本地实现、完整软件回归和ESP32-S3目标编译。安装包在`sdk/python/dist/ai_maker_robot-0.6.0-py3-none-any.whl`，应用在`build/standalone-native-usb/ai_maker_s3.ino.bin`；当前COM5已升级，屏幕固化与清除测试见 [测试与恢复说明](屏幕固化测试与清除恢复_V0.6.md)。真板断电/上电、外部按钮与机械动作需要分别验收；不能把软件模型检查当成实物通过。完整接口见 [V0.6手册](SDK函数说明与示例_V0.6.md)，存储和运行合同见 [Program协议](../protocols/program-v1.md)，路线取舍见 [MicroPython与当前方案](MicroPython与当前方案.md)。

## 16. 边画边录制：begin、end、save（SDK0.6.1）

如果希望保留原来的robot.display绘图写法，使用开始/结束录制。开发板仍使用0.6.0固件，只升级SDK即可。

```python
from ai_robot import Robot

with Robot(port="COM5") as robot:
    robot.display.set(panel="st7735s_128x160", SCL=4, SDA=5,
                      CS=15, DC=7, RES=6, BLK=16, rotation=1)
    robot.start()
    robot.program.begin()
    robot.display.clear()
    robot.display.text("你好，创客！", x=8, y=8)
    robot.wait(3)
    robot.program.end()
    robot.program.save(loop=True, autostart=True)
```

begin之后的支持动作会同步预览并记录；end返回Program快照但不上传；save不传Program时使用最近成功end的快照。wait在预览中也实际等待，固化后同样等待；只记录robot.wait，不自动记录电脑计算耗时。

屏幕/舵机set与start在begin前；GPIO/PWM的set在begin内。begin不是当前屏幕截图，先clear/fill并重画完整内容。cancel丢弃录制和隐式保存快照，不清除板端已有流程；robot.stop仍可随时停止并放弃进行中的录制。

两页完整例子见 [15_screen_record.py](../examples/portable/15_screen_record.py)，错误与范围说明见 [录制教程](绘图录制与固化_V0.6.1.md)。录制不是命名页面系统：模板页用pages.show指定页面ID，pages.text更新当前页控件ID；变化数字只更新运行中的文字，不反复写Flash，也不为每个数字另建一页。pages命名切页/动态文字目前是在线功能，不属于begin/end固化范围。0.7新增下节的定时累加控件；通用变量、传感器绑定和命名页面离线调度仍需另行扩展，不能把静态录制当成动态算法。

## 17. 每秒加一，固化后持续显示（0.7新增）

[16_counter.py](../examples/portable/16_counter.py)只需默认屏幕，保存后RESET或重新接电：

```python
from ai_robot import Program, Robot

program = Program()
program.display.set(panel="st7735s_128x160", SCL=4, SDA=5,
                    CS=15, DC=7, RES=6, BLK=16, rotation=1)
program.display.fill("black")
program.display.text("数字累加", x=8, y=8, color="cyan")
program.display.text("+1 / second", x=8, y=26)
program.display.counter(name="count", start=0, step=1, interval=1,
                        x=8, y=48, width=144, height=20)
with Robot(port="COM5") as robot:
    robot.program.save(program, autostart=True)
```

counter自己按周期持续更新，必须放在主流程最后，不要加loop=True、不要在后面再加Program.wait；旧普通流程的循环用法不变。默认黑底白字，数字区域每次擦除后重画，静态标题不反复刷新。计数RAM运行，重启从start（默认0）开始，不每秒写Flash。延迟时按完整周期追赶；64位上限下一步会溢出时报错停止，不会悄悄变负数。

如果先用begin/end预览背景，取得`flow = robot.program.end()`，再`flow.display.counter(...)`，最后显式`robot.program.save(flow, autostart=True)`。不要调用不存在的Robot.display.counter，也不要以为修改flow会改写隐式save快照。

计数需SDK/固件0.7；矩形最小133×16且在旋转后屏内。停止、禁用、清除和恢复之前备份流程的步骤，以及完整参数/限制见 [数字累加计数指南](数字累加计数器_V0.7.md)。这不是任意Python变量或命名页面系统；本轮实机结果以verification记录为准。

## 18. USB Wi-Fi 配网

需要 USB 数据线、支持 `wifi_provisioning` 的 0.8 固件和 2.4 GHz 网络。旧 1 MiB 布局需先迁移，见 [安装与兼容说明](固件安装与版本兼容.md)。

推荐双击 [配置硬件.cmd](../配置硬件.cmd)，在「串口」同一页选择 COM 口并填写 Wi-Fi 名称、密码。点击「连接并保存」会将成功配置写入开发板，并在窗口和控制台显示状态及 IP；「保存配置」只写电脑上的串口及接线设置。查询和清除均使用当前选择的串口。

想把配网和外设写在一个 `.py` 文件，可以把这一段放在开头，后面继续用同一个 `robot`：

```python
from getpass import getpass
from ai_robot import Robot

with Robot(port="COM5") as robot:
    result = robot.setwifi("创客教室", getpass("Wi-Fi 密码："))
    print(result["provisioning"], result["ip"] or "未取得 IP")
    robot.led.color("cyan")
    robot.wait(2)
```

`setwifi` 需要 SDK 0.8.1，复用当前 USB 会话，最多轮询约 25 秒。无须在每份学员程序里填密码：配网成功后，板端下次通电自动连网；后续代码可以直接从外设操作开始。分享脚本时不要把真实密码写进源码。

SDK 0.8.3 的 `robot.setwifi(name, password)` 默认输出「发送配网请求 → 正在连接路由器并等待获得 IP → 成功并保存或失败」。等待时约每 5 秒提示一次，不输出密码。要关闭提示可传 `progress=False`。连接阶段合并显示：当前固件不能区分路由器认证和 DHCP 等待。`listwifi()` 的 `[]` 只表示查询时没有可用连接；看 `setwifi()` 回执的 `provisioning` 和 `error` 才能判断这次是否成功。

SDK 0.8.2 可用 `print(robot.listwifi())` 查看当前连接，结果例如 `[{'ssid': '创客教室', 'ip': '192.0.2.4'}]`，无连接时为 `[]`。它只查 ESP32 当前连接，不扫描附近热点，也不列电脑的 Wi-Fi 历史。只查时可用 `Robot(port="COM5", read_only=True)`。`robot.clearwifi()` 会断开 Wi-Fi 并清除板端保存的名称和密码，需要普通控制会话；屏幕接线、页面和固化程序均保留。三种操作的可运行文件见 [Wi-Fi 真机测试](../tests/wifi/README.md)，新接口的验证见 [验证记录](verification.md)。

1. 双击 [运行WiFi配网.cmd](../运行WiFi配网.cmd)，或在项目根目录执行 `python examples/portable/17_wifi.py --port COM5`。实际串口请按电脑显示填写。
2. 输入 Wi-Fi 名称和密码。名称可用中文，按 UTF-8 计 1～32 字节，开头和结尾的空格会原样保留。密码输入不显示；个人网络密码为 8～63 个可打印 ASCII 字符，开放网络直接回车。仅 5 GHz、需要网页登录或企业账户认证的网络不适用这套配网流程。
3. 控制台先提示正在配网；拿到 IPv4 后显示「配网成功，已保存」和实际 IP。失败时显示原因，可重新输入。也可打开原页面编辑器，USB 连接后展开「开发板 Wi-Fi 配网」，在网页查看同样的结果。

只查询用 `python examples/portable/17_wifi.py --port COM5 --status`，不会开设备控制会话。清除用 `--clear`，不会删除接线、页面或固化程序。配网和清除需要控制会话；如果原先运行自启计数器，操作完成并断开 USB 会话后按 RESET，可让已保存的计数器重新自启。

```python
from ai_robot import Robot

with Robot(port="COM5", read_only=True) as robot:
    status = robot.wifi.status()
    print(status["state"], status["provisioning"], status["ip"] or "尚无 IP")
```

`robot.wifi.connect(ssid, password)` 返回已受理状态，不等待路由器或 DHCP；无线驱动启动可能有短暂等待。约 20 秒无 IPv4 会显示 `connect_timeout`，检查 2.4 GHz、网络名称和密码。只有 `provisioning == "saved"` 表示这次成功并已保存；旧配置恢复后的 `state == "connected"` 不代表新配置成功。存储失败会保留旧记录，重连不会反复写入 Flash。密码只为重连保存在设备 NVS，状态不会返回密码，电脑不把密码加入接线配置。联网时模拟输入优先选未占用的 ADC1 引脚，实物表现待验证。

完整入口见 [终端示例](../examples/portable/17_wifi.py) 和 [协议](../protocols/wifi-v1.md)；软件与实物状态分别记录在 [验证记录](verification.md)。

**屏幕测试**：打开 [tests/wifi/wifi_screen.py](../tests/wifi/wifi_screen.py) 点运行，或双击同目录的 [运行.cmd](../tests/wifi/运行.cmd)。在文件开头修改 `PORT`；`SCREEN = None` 复用板上保存的屏幕接线，换线时可按 [测试说明](../tests/wifi/README.md) 填写自定义参数。有已保存的 Wi-Fi 时直接使用，尚未配网则提示输入。要换网络可传 `--ssid "网络名"`，密码在终端输入，不进入源码。屏幕显示真实 Wi-Fi 状态、名称和板端 IPv4，日期和北京时间由电脑每秒刷新。按 Ctrl+C 退出，或用 `--seconds 30` 限时测试。原固化计数若被 USB 会话暂停，可在退出后按 RESET 重新自启。
