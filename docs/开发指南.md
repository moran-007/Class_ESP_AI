# Class_ESP_AI：Python 编程与开发指南

更新日期：2026-11-14。适用 SDK `ai-maker-robot 0.5.0`、导入名 `ai_robot`、教学固件 `ai-maker-s3 0.5.0`。**本文件是长期维护的主教程，后续增加功能时在这里同步增加示例与解释。** 完整方法、参数范围和返回值见 [SDK函数手册](SDK函数说明与示例_V0.5.md)。

## 1. 先理解程序在哪里运行

学员写的 Python 在电脑运行，通过 USB 向 ESP32 发指令；ESP32 运行的是 Arduino/C++ 教学固件。安装 SDK 不会烧录开发板，运行一个新的 Python 文件也不会替换固件。

| 层次 | 内容 | 什么时候改变 |
|---|---|---|
| 学员 Python 程序 | 接线参数、绘图、动作和流程 | 每次实验可改 |
| Python SDK | `Robot`、屏幕/音频等公共函数 | 安装或升级 wheel |
| ESP32 固件 | GPIO、SPI、I²S、舵机驱动及 USB 协议 | 增加板端能力/修复板端问题时烧录 |
| 板端保存数据 | 舵机/屏幕映射及默认页面等 | 明确调用相应配置/保存接口 |

当前没有 AI 服务器、识别、聊天或 TTS；音频 URL 接口只接收明确提供的音频。标准库 Turtle 在电脑画图，板端接收图像。

## 2. 安装及第一次运行

安装 Python3.11+；在下载的 wheel 所在文件夹打开终端：

```powershell
python -m pip install ./ai_maker_robot-0.5.0-py3-none-any.whl
```

图片/Turtle 功能另装可选依赖，Python 安装时需带 Tcl/Tk：

```powershell
python -m pip install "./ai_maker_robot-0.5.0-py3-none-any.whl[drawing]"
```

创建自己的 `main.py`，不要命名为 `ai_robot.py`、`serial.py` 或 `turtle.py`，避免遮蔽同名库：

```python
from ai_robot import Robot

with Robot(port="COM5") as robot:
    print(robot.get_info())
```

`port` 是这台电脑的实际串口；COM5 只是示例。`Robot` 创建时连接并握手，不移动舵机。`with` 结束时关闭连接。这段只读信息适合作为第一个测试。IDE 选择安装了 SDK 的 Python 解释器，不需要 `_board.py`。另一台电脑只需重新安装 wheel 和依赖，详见 [跨电脑安装](跨电脑安装与直接导入_V0.5.md)。

## 3. 推荐的程序结构与多外设顺序

不强制使用 with，也可以用 try/finally。同一个串口只创建一个 Robot，屏幕、舵机和音频都挂在它下面：

```python
from ai_robot import Robot

robot = Robot(port="COM5")
try:
    robot.servo.set(pin=14, name="arm")
    robot.start()
    robot.servo.move("arm", 90)
    robot.wait(3)
finally:
    robot.close()
```

此程序运行会驱动舵机；先完成供电、共地，首次卸下连杆。`set` 保存舵机映射且保持维护状态，`start` 退出维护并启动本连接请求的屏幕/音频，`move` 才发出角度动作。`close` 释放输出，不会切断模块电源，不保证舵机回90°。

组合顺序固定为：**audio/display/servo.set → robot.start → digital/analog/pwm.set → 动作**。前一组是外设映射；后一组立即设置 GPIO 模式，维护状态中不能执行。不要在每帧绘图或动作循环中重复 set；配置会停止已有运行输出。

例子中 `pin=14`、`sck=4` 是信号对应的 GPIO，不是排针上的第几脚。系统保留脚、已占用脚会被拒绝。调用 `robot.list_pins()` 查看能力、`reserved` 和 `owner`；能输出不代表当前空闲。屏幕丝印别名见 [对应表](set接口_丝印对照与刷新帧率.md)。

## 4. 板载 RGB 与数字输入/输出

RGB 示例 [09_rgb.py](../examples/portable/09_rgb.py)，只需 USB：

```python
from ai_robot import Robot

with Robot(port="COM5") as robot:
    robot.start()
    robot.led.set(red=8, green=16, blue=3)
    robot.wait(2)
```

这是板载 WS2812 的数据控制，每通道0～32；`led.color("yellow")` 是命名色，`led.off()` 熄灭。当前发布构建的 RGB 在 GPIO48；普通 GPIO 常高不能代替 RGB 数据。

外接按钮接 GPIO2 与 GND，外接 LED 通过匹配限流电阻接 GPIO12 与 GND。以下按下点亮，松开熄灭；LED 极性或接到3.3V的接法会改变点亮逻辑：

```python
from ai_robot import Robot

with Robot(port="COM5") as robot:
    robot.start()
    robot.digital.set(pin=2, mode="input_pullup")
    robot.digital.set(pin=12, mode="output")
    for _ in range(20):
        pressed = robot.digital.read(2) == 0
        robot.digital.write(12, int(pressed))
        robot.wait(0.1)
```

上拉输入松开读1、接地按下读0；输出用 `int(pressed)` 转为0/1。`input`、`input_pullup`、`input_pulldown`、`output` 是四种数字模式。输入悬空会不稳定。ESP32 信号不能直接接5V。

## 5. 模拟输入与 PWM

完整实验见 [07_io_types.py](../examples/portable/07_io_types.py)。下例分别设置 ADC 与 PWM，需要外部模拟信号和 PWM 实验负载：

```python
from ai_robot import Robot

with Robot(port="COM5") as robot:
    robot.start()
    robot.analog.set(pin=1)
    robot.pwm.set(pin=17)
    print(robot.analog.read(1))
    robot.pwm.write(17, 25)
    robot.wait(3)
```

ADC 读原始12bit计数0～4095，不是校准后的伏特。GPIO1～20是 ADC 候选，仍受保留脚/资源占用限制。PWM 固定1kHz，占空比整数0～100%，适合本实验的 LED 调光；GPIO不能直接驱动电机等大电流负载。PWM 不是真正连续模拟电压，`robot.analog.write(...)` 明确报不支持 DAC。旧 `gpio/adc/pwm` 调用继续兼容。

## 6. SG90 舵机

[10_servo.py](../examples/portable/10_servo.py) 展示单舵机，两项主要配置为信号脚与逻辑名：

```python
from ai_robot import Robot

with Robot(port="COM5") as robot:
    robot.servo.set(pin=14, name="arm", min_angle=30, max_angle=150)
    robot.start()
    robot.servo.move("arm", 90)
    robot.wait(3)
```

`set` 的课堂脉宽默认1000～2000µs，逻辑角度限制默认30～150。旧 `configure` 默认脉宽500～2500µs，两者不能混为同一默认值。根据实际舵机校准；当前没有真实位置反馈。可以用不同名称/引脚配置多个舵机，最多4个；独立匹配供电且与 ESP32 共地，不能从信号 GPIO 给舵机供电。

程序退出后停止 PWM 是会话清理，不是把信号口永久锁死。希望长期控制时保持 Python 程序运行；下一程序可以重新配置。希望脱离电脑运行完整行为，需要另行开发板端逻辑，不是把当前 Python 文件拷进去。

## 7. SPI 屏幕：文字、图形与图片

可复制 [11_display.py](../examples/portable/11_display.py)：

```python
from ai_robot import Robot

with Robot(port="COM5") as robot:
    robot.display.set(panel="st7735s_128x160", SCL=4, SDA=5,
                      CS=15, DC=7, RES=6, BLK=16, rotation=1)
    robot.start()
    robot.display.fill("black")
    robot.display.text("你好，创客！", x=8, y=8)
    robot.display.rect(8, 40, 80, 20, color=(55, 88, 99), filled=True)
    robot.wait(10)
```

`panel` 决定初始化序列与尺寸；支持 ST7735S128×160、ST7789240×320/240×240。改型号同时核对实际分辨率。SCL 在这里是 SPI 时钟，SDA 是 MOSI，不表示 I²C；RES 是复位，BLK 是可选背光。信号都可以按允许 IO 自定义。未接可控背光时填 `backlight=-1`；供电脚不填 IO 参数。

`rotation=1` 时本 ST7735 的有效画面为160×128，坐标不能超界。屏幕颜色三元组是0～255，与板载 RGB 的0～32不同。中文使用内置字库，不覆盖任意 Unicode 字符。

```python
# 已 set/start 的同一 robot 上使用；需要 Pillow 和自己的图片文件。
result = robot.display.image("picture.png", fit="contain")
print(result["transfer_seconds"])
```

`contain` 保留整图并补边，`cover` 居中裁剪填满。`display.set(..., fps=10)` 只是电脑端整屏图片发送帧开始上限，不是面板刷新率，也不保证达到10帧。文字/图形 API 不受此上限限制。

## 8. 页面模板与默认页面

页面是受约束的 JSON 布局模型，不执行学员上传的 JavaScript/HTML。电脑网页编辑器可以编辑/导入导出页面和图标，保存给板端；详见 [页面与Turtle说明](页面编辑器与Turtle_V0.4.md)。

在**已经配置屏幕并 start 的同一 robot**上使用，示例文件尺寸为160×128：

```python
robot.pages.upload("page_demo.json")
robot.pages.show("home")
robot.pages.text("status", "Python更新成功")
print(robot.pages.info())
```

把仓库 [page_demo.json](../examples/pages/page_demo.json) 放到程序工作目录。`upload` 保存模板但不启用开机显示；`show` 显示页面；`text` 只临时更新当前控件，不回写模板。明确需要关闭 Python/复位恢复此页时再执行 `robot.pages.startup("home", enabled=True)`；只影响屏幕，不恢复舵机动作。`pages.download()` 读回模板，`pages.clear()` 清空且保持维护。完整大小/控件限制见 [页面协议](../protocols/pages-v1.md)。

## 9. Turtle 画好再发送

[08_turtle.py](../examples/portable/08_turtle.py) 使用标准库窗口；发送辅助也在安装包内：

```python
import turtle
from ai_robot.turtle import finish

screen = turtle.Screen()
pen = turtle.Turtle()
pen.circle(60)
pen.hideturtle()
finish(screen, port="COM5", panel="st7735s_128x160",
       SCL=4, SDA=5, CS=15, DC=7, RES=6, BLK=16)
```

这个写法先画图，点击“发送”或 Enter 时才连接。若开头已经创建并配置了 Robot，则结尾使用 `finish(screen, robot=robot)`，不要再传另一组 COM/IO，也不要为同一端口再开连接。关闭 Turtle 窗口会关闭它接管的整条连接，包括同一 Robot 的其他输出。发送的是临时像素画面，不替换默认模板。电脑窗口要保持可见，不能最小化后捕获。

## 10. INMP441 收音

先单独运行 [02_audio_record.py](../examples/portable/02_audio_record.py)：

```python
from ai_robot import Robot

with Robot(port="COM5") as robot:
    robot.audio.set(bclk=42, ws=41, din=21, dout=-1, sd=-1)
    robot.start()
    robot.wait(0.2)
    clip = robot.audio.record(seconds=3)
    clip.to_wav("recording.wav")
    print(clip.levels)
```

麦克风3.3V供电并共地：BCLK/SCK 是时钟，WS 是声道时钟，麦克风 SD 是数据，接 ESP32 的 `din`。L/R 接地选 left；接高电平时填 `mic_channel="right"`。`dout=-1, sd=-1` 关闭功放方向。短等待仅帮助上电稳定，不构成具体模块启动时间保证。

录音返回 `AudioClip`；WAV 保存到当前工作目录。`all_zero` 帮助排查无数据，`clipped_samples` 提示削顶，但非零不等于真实人声质量合格。此版本一次录音最多30秒，无重采样或 MP3 编解码。

## 11. MAX98357A 功放、本地与 URL 音频

先运行 [03_audio_tone.py](../examples/portable/03_audio_tone.py) 的低幅测试音：

```python
from ai_robot import Robot, AudioClip

with Robot(port="COM5") as robot:
    robot.audio.set(bclk=42, ws=41, din=-1, dout=40, sd=39, volume=20)
    robot.start()
    robot.audio.play(AudioClip.tone(frequency=440, seconds=1, volume=0.1))
```

功放 BCLK/LRC 对应 bclk/ws，DIN 接 ESP32 `dout`，SD/EN 是关断控制，**与麦克风 SD 的数据含义不同**。功放匹配供电并共地，扬声器接功放输出，不能把 BTL 任一输出端接 GND。`volume=20` 是播放软件增益百分比，不是麦克风增益；tone 的 volume 是生成信号的幅度。

两个模块可共用一组 BCLK/WS，数据方向独立，当前采用“录完再播”的半双工：[04_audio_echo.py](../examples/portable/04_audio_echo.py)。停止录放用 `audio.stop()`，结束 I²S 硬件用 `release()`，需要释放映射让其他功能使用 IO 时用 `unconfigure()`。`sd=-1` 时软件不能保证功放硬件关断。

```python
# 同一 robot 已 set/start；文件或网址须由你明确提供。
robot.audio.play_file("recording.wav")
robot.audio.play_url("http://127.0.0.1:8000/recording.wav")
```

URL 示例要先在音频文件目录运行 `python -m http.server 8000 --bind 127.0.0.1`，SDK 不自动创建服务器。这里只是文件音频服务，不是 AI 服务器。对应短例为 [05](../examples/portable/05_audio_file.py)、[06](../examples/portable/06_audio_url.py)。

本地、收音、URL 都用同一个 `AudioClip`：**16000Hz、单声道、有符号16bit、小端 PCM**。WAV 只是文件容器，不能把 WAV 头当成 PCM 发给板端/未来服务。原始字节和元数据衔接示例：

```python
from ai_robot import AudioClip

clip = AudioClip.from_wav("recording.wav")
raw = clip.to_pcm()
metadata = clip.to_wire()
same = AudioClip.from_wire(raw, metadata)
```

裸 PCM URL 需要显式 format="pcm_s16le" 且用参数或响应头声明16000Hz/1声道。当前没有 ASR/TTS/对话 API、压缩音频解码或后台自动云请求。更多错误与格式限制见 [音频说明](数字模拟IO与音频测试_V0.5.md)。

## 12. 维护、故障与退出

| 现象/回执 | 先做什么 |
|---|---|
| ImportError/ModuleNotFoundError | 核对 IDE 解释器和 pip 安装目标；避免同名脚本遮蔽库 |
| COM 被占用 | 关闭自己运行的 Python/Turtle/串口监视器后重跑；不并行打开同一串口 |
| 不兼容固件/能力缺失 | 确认 ai-maker-s3 及版本；旧 AI 固件/白灯诊断固件不是教学固件 |
| PIN_RESERVED / RESOURCE_CONFLICT | 看 list_pins 的 reserved/owner，改允许的空闲 IO |
| MAINTENANCE_REQUIRED/维护状态错误 | 检查映射 set → start → 即时 GPIO set 的顺序 |
| RequestTimeout | 动作可能执行，不自动重发；先查看设备状态并排查连接 |
| 屏幕有回执但黑屏/音频有数据但无声 | 分别核对供电、信号、型号、背光/SD和声道；回执不等于物理效果 |

换线前先 `robot.maintenance.enter()` 确认，再断电换线；修改代码后上电配置、start。普通退出用 close；会话异常时6秒租约是最后清理保障，不是日常关闭替代品。维护标志、屏幕/舵机配置可持久化；音频映射只属于当前会话。

## 13. 想添加功能时改哪里

| 内容 | 位置 | 要一起改的内容 |
|---|---|---|
| Python 公共 API | sdk/python/src/ai_robot/ | 本指南、完整手册、portable示例、SDK测试、版本 |

按 [CONTRIBUTING](../CONTRIBUTING.md) 的功能文档模板交付。可以只增加电脑端绘图逻辑而不改固件；需要新的传感器协议/板端时序时通常要同时改固件和 SDK。不要让 `__getattr__` 或示例把未实现功能模拟成成功。
