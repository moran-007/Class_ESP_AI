# ESP32 固件安装与版本兼容

## 16 MiB 教学板布局：USB 恢复与 OTA 预留

新 `firmware/ai_maker_s3/partitions.csv` 适合核实为 16 MiB Flash 的 ESP32-S3。原生 USB / GPIO48 的配网固件约 1.28 MB，超出旧 1 MiB 布局，在新布局每个应用区内均有约 1.77 MiB 余量。

| 分区 | 起始 | 容量 | 用途 |
|---|---:|---:|---|
| NVS / PHY | `0x9000` / `0xf000` | 24 / 4 KiB | 原地址和容量保持，保存接线、页面、程序、网络配置和校准信息 |
| factory | `0x10000` | 3 MiB | USB 离线安装和恢复 |
| ota_0 / ota_1 | `0x310000` / `0x610000` | 各 3 MiB | 预留给未来轮流写入的联网升级 |
| otadata | `0x910000` | 8 KiB | OTA 启动槽记录；首次迁移校验为空 |
| storage | `0x920000` | 6.875 MiB | 预留 LittleFS 数据区，当前不自动格式化 |

这是两个升级方式共用的布局。当前可经 USB 安装，是否配 Wi-Fi 不影响该入口。OTA 仅预留分区，下载、签名校验、切换和回滚流程尚未实现。未来启用 OTA 后，USB 恢复还需要处理对应分区表的 OTA 启动选择记录，才能让设备回到 factory。

**已有数据的板不要使用 Arduino IDE 的默认 Upload、`arduino-cli upload`、`boot_app0.bin` 或整片 merged 镜像。** Arduino 通用上传配方仍会向 `0xe000` 写 OTA 初始化数据，此处属于本项目 NVS。`firmware/build.ps1` 会生成与自定义布局一致的 `flash_args` 和仅供空白板使用的 merged 镜像。首次迁移时先完整读回、检查旧布局和新分区覆盖范围，再用 esptool 定点写入应用、匹配的 16 MiB bootloader 和分区表；升级前后的验证见 [实测记录](verification.md)。

对已完成迁移、仍从 factory 启动的本机 COM5，后续离线升级只需检查应用不超过 3 MiB，然后写应用，不再写引导程序或分区表。项目根目录下的示例：

```powershell
esptool --chip esp32s3 --port COM5 write-flash 0x10000 build/ota-ready-native-usb/ai_maker_s3.ino.bin
```

## 0.7数字累加（2026-11-15 COM5 升级记录）

计数器需要SDK和固件0.7.0的standalone_counter能力；旧0.6仍可运行普通Program/录制，但不能执行counter。应用为`build/counter-native-usb/ai_maker_s3.ino.bin`，721984字节；本机核对原分区和备份后，只升级0x10000应用，未更换bootloader/分区或擦除NVS。

原有启用中的A/B程序及策略、原配置和页面已备份；升级后完整保留验证通过，再保存本次计数流程。用户已确认每秒正常加一、显示正常；当前保留计数运行，清除和恢复之前程序见 [tests/counter](../tests/counter/README.md)。固化计数不保存每秒的数值，重启从start开始。GitHub已发布版本仍0.5.0，不能改下载URL假定0.7附件已存在。

下述0.6内容为此前升级记录；原分区核对和备份原则继续适用。

## 0.6固化功能（此前COM5升级记录，尚未发布）

当前新增的Program需要SDK/教学固件0.6.0；旧GitHub0.5.0附件不支持。0.6本地wheel为`sdk/python/dist/ai_maker_robot-0.6.0-py3-none-any.whl`，应用为`build/standalone-native-usb/ai_maker_s3.ino.bin`，717376字节，仍小于已核对原板1MiB应用分区。构建目标、GPIO48和原生USB条件不变；下文0.5应用偏移/分区核对原则同样适用，不能仅修改文件名而跳过核对和备份。首次升级后，修改支持的Program只需要save，不需要再次烧整套固件。

固化模型与开机策略存于独立NVS键，不改变原live配置schema。回退0.5不会自动清除这个键；将来再次升级0.6，原来启用的流程仍可能按开机策略执行。需要禁用时先用0.6的program.disable/clear完成，不把换回旧固件当成删除程序。后续屏幕测试已在备份后将0.6应用写入COM5，原配置和默认页面验证保留；复位后无会话执行回执通过，屏幕现场观察及实际断电供电验证分别记录，不混为一项。

以下为已发布0.5.0的历史安装条件和附件名称，不代表0.6附件已经发布。

## 发布对象

Class_ESP_AI 0.5.0 提供 Python wheel、Arduino/C++ 源码、构建脚本、示例、文档以及 ESP32-S3 **应用镜像**。不是 MicroPython 固件；Python 在电脑运行。仓库尚无定制PCB制造文件，不代表已完成定制板设计。

| 项目 | 当前版本/条件 |
|---|---|
| Python | 3.11+，SDK ai-maker-robot0.5.0 |
| 导入名 | ai_robot |
| 固件 | ai-maker-s3 0.5.0，USB协议v1 |
| 当前目标 | ESP32-S3，16MiB Flash、8MiB OPI PSRAM、原生USB、板载WS2812 GPIO48 |
| 编译核心 | Arduino-ESP32 3.3.12 |
| ArduinoJson | 7.4.3 |
| 显示依赖 | Adafruit GFX1.12.6；ST7735/ST7789 1.11.0；BusIO1.17.4；U8g2_for_Adafruit_GFX1.8.0 |
| 音频 | 原生USB传输，INMP441/MAX98357A，半双工16k/mono/PCM16LE |

外部 IO 在 Python 中配置，屏幕型号不是固件构建型号；换 ST7735/ST7789 或允许的信号 IO 通常不需要重刷。换芯片系列、Flash/PSRAM规格、板载RGB脚、USB路径等，需要重新核对构建与板级配置，不能只改串口。

## 现有开发板的应用升级

当前已验证板的原分区：NVS0x9000长0x6000、phy0xF000长0x1000、factory应用0x10000长0x100000（1MiB）。0.5.0应用688832字节，适合此应用区。实际用户设备仍须自行读回核对，不能仅凭“ESP32-S3”或COM5就认定相同。

Release 中 `ai-maker-s3-0.5.0-native-usb-rgb48.bin` 与本机 `build/audio-native-usb/ai_maker_s3.ino.bin` 是相同字节，只改了附件名称。固件ZIP只放应用、清单和说明；**没有公共 NVS/整板备份，不包含可直接覆盖原板的参考merged镜像**。

升级前停止 Python/串口监视器，核对芯片、分区、应用大小，保存本机私有备份并验证SHA256。已确认上述原分区且具备恢复条件时，使用 esptool：

```powershell
python -m pip install "esptool==5.3.1"
python -m esptool --chip esp32s3 --port COM5 write-flash 0x10000 ./ai-maker-s3-0.5.0-native-usb-rgb48.bin
```

此命令会写入应用，**不是自动识别分区的通用刷机器**。仅 COM5 与文件路径需按实际修改还不够，前述条件也必须满足。不要执行 erase-flash，不要把应用写到0x0，也不要为“保留配置”复制其他人的NVS。

成功后运行 `examples/portable/01_info.py`，检查 firmware_family=ai-maker-s3、firmware_version=0.5.0 和能力。旧AI固件、常亮白灯诊断固件不是兼容目标。不能用成功握手代替实际屏幕/声音验收。

## 空白板或分区不同的板

只有应用 BIN 不能初始化完全空白的 Flash。确认是匹配的 16 MiB ESP32-S3 空白板后，用 `firmware/build.ps1` 编译，按它生成的 `flash_args` 用 esptool 写入各段，或使用同一构建的空白板专用 merged 镜像。此布局不要用 Arduino 默认 Upload 或 `arduino-cli upload`：通用配方会把 `boot_app0.bin` 写进项目的 NVS 区间。

`firmware/build.ps1` 只编译，不自动上传。旧版本使用 fatflash 参考布局；当前构建使用本页的 16 MiB 教学布局，不能直接覆盖布局未知的用户板。当前公开 Release 不提供此新布局的刷写包。

```powershell
arduino-cli core update-index
arduino-cli core install esp32:esp32@3.3.12
arduino-cli lib install ArduinoJson@7.4.3
arduino-cli lib install "Adafruit GFX Library@1.12.6"
arduino-cli lib install "Adafruit ST7735 and ST7789 Library@1.11.0"
arduino-cli lib install "Adafruit BusIO@1.17.4"
arduino-cli lib install "U8g2_for_Adafruit_GFX@1.8.0"
./firmware/build.ps1 -Transport native-usb -BuiltinRgbPin 48
```

RGB38的板可显式传 `-BuiltinRgbPin 38` 另行构建；不代表其它板级资源已自动适配。UART构建保留基础SDK能力，但禁用本版音频流。

## 升级、回退与兼容

- Python脚本和IO参数修改不要求重新烧录；需要新的板端能力时才升级固件。
- 0.5.0 SDK 保留旧 GPIO/ADC/PWM、servo.configure、display.configure 和 with 写法；新增音频要求支持对应能力的固件。
- 音频引脚映射仅属于当前会话；关闭连接后清除，不在下次开机自动收音。
- 0.5.0 未增加新的持久配置字段；维护标记/屏幕/舵机/页面仍有各自持久化行为。回退之前先保存自己的有效配置与页面，核对旧版格式。
- 回退使用自己核对过的旧应用及原分区；私有备份留在本机，不上传GitHub。
- 本次公开发布属于0.x教学版本；真实音频质量仍待用户连接模块验收，发布说明不会将其写为通过。
