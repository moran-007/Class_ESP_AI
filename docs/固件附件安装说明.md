# 教学固件 0.8.0 附件安装说明

目标板：ESP32-S3，16 MiB Flash，8 MiB OPI PSRAM，原生 USB，板载 RGB 接 GPIO48。不同 Flash、PSRAM、USB 接法或 RGB 引脚的板，请重新核对构建目标。

| 包内文件 | 地址与用途 |
|---|---|
| `ai-maker-s3-0.8.0-native-usb-rgb48.bin` | `0x10000`，应用镜像，1,283,712 字节 |
| `bootloader-16m.bin` | `0x0`，16 MiB 引导程序 |
| `partitions-16m.bin` | `0x8000`，项目分区表 |
| `partitions.csv`、`flash_args`、`firmware-manifest.json` | 分区布局、空白板写入地址、各文件校验 |

先关闭 Python 程序和串口监视器，在解压目录使用 esptool 5.3.1 或与项目工具链匹配的版本。示例的 `COM5` 换成实际串口。确认下载的文件哈希与清单一致。

## 已使用本项目 16 MiB 分区的开发板

确认 factory 从 `0x10000` 开始、容量 3 MiB、设备仍从 factory 启动，并做好本机备份。只写应用，保留现有接线、页面、固化程序和 Wi-Fi 设置：

```powershell
esptool --chip esp32s3 --port COM5 write-flash 0x10000 ./ai-maker-s3-0.8.0-native-usb-rgb48.bin
```

## 匹配的全新空白板

只有确认板卡匹配且 Flash 内没有需要保留的数据，才使用这条命令：

```powershell
esptool --chip esp32s3 --port COM5 write-flash 0x0 ./bootloader-16m.bin 0x8000 ./partitions-16m.bin 0x10000 ./ai-maker-s3-0.8.0-native-usb-rgb48.bin
```

地址与包内 `flash_args` 一致。初次启动由 factory 应用负责初始化空白 NVS；不用另写 `boot_app0.bin`。

## 旧 1 MiB 或未知分区的板

不要执行以上两条命令。先读回实际分区、核对 Flash 容量并备份，再制定迁移方案。**不要执行 `erase-flash` 或 Arduino 默认 Upload**；默认上传会在 `0xe000` 写入 `boot_app0.bin`，与项目保留的 NVS 重叠。详细布局见 [固件安装与版本兼容](https://github.com/moran-007/Class_ESP_AI/blob/v0.8.3/docs/固件安装与版本兼容.md)。

刷写后先运行源码包 `examples/portable/01_info.py`，确认 `ai-maker-s3`、固件 `0.8.0` 和 `wifi_provisioning` 能力，再做外设测试。OTA 传输尚未接入。若需回退，使用自己的备份及与原分区匹配的旧应用、分区表和引导程序；附件不含任何 NVS 或用户数据。
